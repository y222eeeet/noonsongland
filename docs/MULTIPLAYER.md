# 실시간 송이 연결

## 서버 설정

1. Supabase Authentication에서 익명 로그인을 활성화한다.
2. SQL Editor에서 `supabase/migrations/20261109_realtime_campus.sql`을 실행한다.
3. Realtime 설정에서 공개 채널 허용을 끄고 비공개 채널을 사용한다.
4. 배포 환경에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 설정한다.

위 설정은 이 작업에서 원격 서버에 적용하지 않았다.

## 확인 방법

- 서로 다른 브라우저로 입장해 상대 캐릭터와 닉네임, 접속 인원을 확인한다.
- 양쪽에서 이동·회전·한숨을 실행하고 상대 화면을 확인한다.
- 한쪽을 멈춘 상태에서 다른 브라우저를 새로 열어 캐릭터가 나타나는지 확인한다.
- 탭을 닫고 접속자에서 제거되는지 확인한다. 네트워크 단절 감지에는 지연이 있을 수 있다.
- 네트워크를 끊었다 복구하고 접속자 목록과 위치가 복구되는지 확인한다.
- 같은 브라우저의 두 탭에서는 캐릭터가 두 개이고 사용자 수는 중복 제외되는지 확인한다.

## 구현 범위와 한계

Presence로 접속 목록, Broadcast로 초당 10회 위치·방향·동작을 전달한다. 영구 위치 테이블은 없다. 원격 캐릭터는 위치를 부드럽게 따라가고, 한숨 표정과 크기 변화를 재생한다. 한숨 구름 효과는 아직 공유하지 않는다. 백그라운드 탭은 전송을 중단하며, 10초 이상 상태가 오지 않은 캐릭터는 숨긴다. 화면을 다시 열면 전송을 재개한다.

접속별 ID로 여러 탭을 구분하고 사용자 ID로 인원을 집계한다. 서버가 움직임이나 메시지의 사용자 ID를 검증하는 권위 서버 구조는 아니다. 채널 정책은 인증된 참여자의 접근을 제한하지만 참여자가 보낸 페이로드의 신원을 보증하지 않는다. 경쟁 게임이나 신뢰가 필요한 집계로 확장할 때는 서버 검증이 필요하다. 렌더링은 다른 송이 최대 100명으로 제한한다.

기존 공유 그림자 updater 호출과 바닥 생성 코드는 유지했다. 저장소에 WORLD_RULES.md가 없어 해당 문서 확인은 불가능했다.

검증: 배포 빌드 통과. 실제 Supabase 연결을 이용한 두 브라우저 검증은 서버 정책 적용 후 필요하다.
